## 製品概要

### 背景(製品開発のきっかけ、課題等）

食物アレルギーや食事制限のある訪日旅行者が、日本語のメニューを理解し、店員に原材料や対応可否を確認する際の言語の壁を減らす。

### 製品説明（具体的な製品の説明）

メニューを撮影し、料理の英語説明とアレルゲン・食事制限の予測を確認するWebアプリ。同じスマートフォンを店員に渡して日本語で回答してもらい、結果を英語で確認する。

### 特長

#### 1. メニュー画像から確認項目を整理

指定されたアレルゲン29種（特定原材料9品目・準ずる20品目）と食事制限4種（Vegan・Vegetarian・Halal・No alcohol）を選択し、AIが候補と根拠を提示する。

#### 2. スマートフォン1台で店員に確認

利用者は英語、店員は日本語の画面を使う。店員回答は「分からない」を含む4択。ログインや店舗選択を省略しても利用できる設計とする。

#### 3. 過去の回答を予測に反映

同じ店舗・料理・確認項目の過去回答をAIの候補と組み合わせ、根拠・回答件数・最終確認日時を示す。

### 解決出来ること

メニューの理解と店員への確認を補助し、料理選びの判断材料を提供する。AIの予測や未認証の店員回答によって、安全性や食事制限への適合を保証するものではない。

### 今後の展望

撮影から店員確認までの基本機能を優先し、その後に地図表示・公開メニュー閲覧・任意のアカウント登録と本人設定の保存・本人が読み込んだメニューの履歴を追加する。公開画面では他の利用者の公開回答も集計する。

### 注力したこと（こだわり等）

* AIの予測と店員の回答を区別し、「分からない」を不使用・対応可の根拠にしない設計。
* 登録時の利用者同意と店員確認時の店員同意がそろい、店舗が選ばれた回答のみを公開し、メニュー画像や利用者の設定を公開しない設計。

## 開発技術

### 活用した技術

以下は採用予定の技術です。

#### API・データ

* Gemini：メニュー画像の解析。
* Google Places API（New）：周辺飲食店の検索。
* Google Maps JavaScript API：地図表示（追加実装）。

#### フレームワーク・ライブラリ・モジュール

* React Native・Expo（TypeScript）：Web画面。
* FastAPI（Python）：API・予測計算。
* Supabase PostgreSQL・Storage：解析結果・回答・非公開画像の保存。
* Vercel：Web・APIの公開先。

#### デバイス

* 利用者のスマートフォン（Webブラウザ・カメラ）。

#### ハッカソンで開発した独自機能・技術

独自機能は設計段階です。

* AIの候補と過去の店員回答を組み合わせる予測処理（[API仕様](docs/api.md)）。
