Meelyze+（メーライズプラス）は、食物アレルギーや食事制限のある訪日旅行者が、日本の食文化を楽しむために、メニューの理解と店員への確認を支援するWebアプリです。

## 製品概要

### 背景(製品開発のきっかけ、課題等）

食物アレルギーや食事制限のある訪日旅行者にとって、日本語のメニューから原材料を理解し、店員に使用食材や交差接触を確認することは容易ではありません。こうした言語の壁を減らし、旅行先での食体験の選択肢を広げることを目指しています。

### 製品説明（具体的な製品の説明）

メニューを撮影すると、AIが料理名や英語の説明、アレルゲン・食事制限に関する候補と根拠を提示します。利用者が同じスマートフォンを店員に渡し、日本語の画面で回答してもらうことで、確認結果を英語で確認できます。また、地図から周辺の飲食店を探し、過去の利用者が読み込んだ公開メニューや、公開に同意された店員回答の集計を閲覧できます。現在はこれらの主要画面を実装しています。

### 特長

#### 1. メニュー画像から確認項目を整理

アレルゲン29品目（表示義務9品目と表示推奨20品目）および食事制限4種類（Vegan・Vegetarian・Halal・No alcohol）を対象に、Geminiが料理の候補と根拠を整理します。現行のWeb画面はアレルゲン29品目の選択に対応し、食事制限4種類はAPI・DB側の実装まで完了しています。

#### 2. スマートフォン1台で店員に確認

利用者向けは英語、店員向けは日本語で表示します。店員はアレルゲンについて「含まれる」「含まれない」「同じ料理器具を使っている」「わからない」の4択で回答し、確認結果を保存できます。現在のWeb画面はログインが必要ですが、店舗を選ばずに撮影・解析へ進むことはできます。ゲスト利用はAPIでは対応済みで、Web画面への導入は今後の課題です。

#### 3. 過去の回答を予測に反映

同じ店舗・料理名・確認項目に対する過去の店員回答を集計し、回答件数・最終確認日時・回答の不一致を扱う処理をFastAPIに実装しています。回答が古いほど集計上の重みを小さくし、「わからない」や器具の共用を「含まれない」の根拠にはしません。**AIの候補と店員の回答は区別して表示する方針で、単一の安全確率には合成しません。** また、地図上の飲食店を選ぶと、過去の利用者による公開メニューと、公開条件を満たした回答の集計を確認できます。地図からの公開情報の閲覧は実装済みですが、個別の解析結果画面での履歴件数・日時・スコアの詳細表示は今後追加する予定です。

### 解決出来ること

メニューの理解から店員への確認までを1台のスマートフォンで支援します。さらに、周辺店舗の地図と過去の利用者が共有した公開情報から、訪問前にも料理選びの判断材料を得られます。ただし、AIの予測や未認証の店員回答によって、安全性や食事制限への適合を保証するものではありません。実際に食べる前の店舗への確認が必要です。

### 今後の展望

公開環境とスマートフォン実機で撮影・解析・店員確認・保存までの一連の動作を検証し、食事制限4種類の画面対応、ゲスト利用、複数人プロファイル、本人のメニュー履歴表示などを追加します。地図表示・公開メニュー閲覧・アカウント機能の主要部分はすでに実装しています。

### 注力したこと（こだわり等）

* **安全性への配慮：** AIの予測と店員の回答を分離し、「わからない」や未確認を不使用・対応可の根拠にしない仕組みを実装。
* **回答の再利用：** 店舗・料理・確認項目を限定して過去の回答を集計し、日時や回答の矛盾を考慮する処理を実装。
* **プライバシーと整合性：** メニュー画像は非公開で保管し、公開条件を満たす回答の集計のみ公開。店員回答と公開可否をまとめて保存し、再送による二重登録を防止。
* **改善予定：** 現行の登録画面では利用者の公開同意が固定値となっているため、公開前に明示的に選択できるよう改善する予定。

## 開発技術

### 活用した技術

以下は現在採用した技術です。

#### API・データ

* Gemini（Google GenAI SDK）：メニュー画像の解析、料理の英語説明・候補・根拠の構造化。
* Google Places API（New）：周辺飲食店の検索。
* Google Maps JavaScript API：周辺店舗の地図表示と公開メニューへの導線。
* Upstash Redis：公開APIのレート制限。

#### フレームワーク・ライブラリ・モジュール

* React Native・Expo・Expo Router（TypeScript）：スマートフォン向けWeb画面。
* FastAPI（Python）：API、画像解析の連携、判定処理、認証・アクセス制御。
* Supabase PostgreSQL・Storage：料理・店員回答・アカウント情報、非公開画像の保存。
* Vercel：Web・APIを別プロジェクトで公開する構成。APIの接続先は用意済みですが、公開環境での全フロー検証は未完了です。

#### デバイス

* 利用者のスマートフォン（Webブラウザ・カメラ）。店員も同じ端末上で回答します。

### 独自技術

#### ハッカソンで開発した独自機能・技術

* **AIと店員回答を分離した判定処理：** AIの根拠、今回の店員回答、同じ店舗・料理・項目の回答履歴を区別し、履歴の時間減衰や回答の不一致を扱う仕組みを実装（[API仕様](docs/api.md)）。
* **店員回答の一括保存と重複防止：** 店員回答・公開可否をSupabaseのRPCで一括保存し、同一の`request_id`による再送で重複登録を防止（[DB仕様](docs/database.md)）。
* **公開情報の制御：** 店舗の選択、利用者と店員の同意に基づき、公開対象の回答を制御。メニュー画像や個人設定は公開しない設計（[要件](requirements.md)）。
