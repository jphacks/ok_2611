# 00 利用者側で開発用プロジェクトと認証情報を準備する

状態：未着手。担当：利用者（Supabaseの管理アカウントを操作できる人）。

## 必要な理由と進め方

クラウド上の開発用Supabaseプロジェクトは、03の対象環境への適用・実Storage検証に必要。既存の開発用プロジェクトがあれば再利用でき、新規作成は不要。01・02のSQL作成とローカル検証は、このタスクと並行して進められる。[CLIのローカル開発とクラウド接続](https://supabase.com/docs/guides/local-development/cli/getting-started)

このセッションでは、Supabase管理アカウントの認証・対象プロジェクト・利用可能な接続情報が確認できていない。以下は現状では私が単独で完了できない作業をまとめたもの。管理用認証と対象が用意された後のCLI接続・SQL適用・検証は私が担当できる。

## 利用者側の作業

### 1. 開発用プロジェクトを用意する

- [ ] [Supabase Dashboard](https://supabase.com/dashboard) にログインする。必要ならアカウント作成・メール認証・MFA・組織への参加を済ませる。
- [ ] 使用するOrganizationと開発用プロジェクトを決める。既存プロジェクトがあれば、開発用か、既存データがあるかを確認する。
- [ ] 新規の場合は、プロジェクト名・リージョン・プランを選び、DBパスワードを設定して作成する。組織・契約・費用に関する判断は利用者が行う。作成後は起動完了を確認する。
- [ ] プロジェクト名、Project Ref、リージョン、開発用であること、既存データの有無を共有する。SQL Editorでテーブルやバケットを先に作らず、構築は01〜03のマイグレーションに任せる。

アカウントへのログイン操作と対象・費用の選択は、現在の認証・情報だけでは代行できない。

### 2. CLIの管理用認証を用意する

- [ ] 01でCLIが使えるようになった後、利用者の端末で `supabase login` の認証を完了する。代わりに実行環境へ `SUPABASE_ACCESS_TOKEN` を設定する方法もある。
- [ ] CLIを実行する環境から、指定プロジェクトを参照できる権限があることを確認する。別の端末でログインしただけでは、この作業環境に認証は引き継がれない。

CLIの管理用アクセストークンは、後述のAPI用Secret Keyとは別物。ログイン操作・トークン発行が必要な場合は利用者が行い、その値を実行環境に設定する。[CLI認証の公式手順](https://supabase.com/docs/reference/cli/supabase-login)

### 3. 接続情報を取得・設定する

| 情報 | 用途 | 引継ぎ方法 |
|---|---|---|
| Project Ref | `supabase link` の接続先 | 値を共有可能 |
| Project URL / `SUPABASE_URL` | SDK・APIの接続先 | 値を共有可能 |
| `SUPABASE_SECRET_KEY` | サーバーからDB・Storageを操作するSecret Key | 秘密情報として実行環境へ設定 |
| DBパスワード | CLIのDB接続・マイグレーション適用 | 秘密情報として保持。必要時に対話入力または `SUPABASE_DB_PASSWORD` で設定 |
| DB接続先（host・port・database・user・接続方式） | SQL検証・複数接続テスト | Connect画面で取得。パスワードを含む接続文字列は秘密情報として扱う |
| CLIの管理用認証 | プロジェクト参照・リンク | 手順2のログインまたは環境変数を使用 |

- [ ] Project URLと接続先をConnect画面で確認し、Secret KeyをAPI Keys画面から取得する。API設定名は [API README](../../apps/api/README.md#環境変数) に合わせる。[キーの取得方法](https://supabase.com/docs/guides/getting-started/api-keys#find-your-keys)
- [ ] 秘密値はパスワード管理ツールや実行環境の秘密情報設定で管理する。チャット・タスク文書・Gitに値を記載せず、設定済みの変数名・利用できる環境だけを共有する。
- [ ] CLI／検証用接続とAPI用接続が同じ開発プロジェクトを指していることを確認する。

今回の変更範囲は `supabase/` のため、`apps/api/.env` やVercelへの設定作業はAPI担当へ引き継ぐ。フロントへサーバー用Secret Keyを渡さない。
