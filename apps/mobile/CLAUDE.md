# apps/mobile 開発ガイド

このファイルは `apps/mobile` の作業に適用する。仕様の正本はリポジトリ直下の `requirements.md`、`docs/screens.md`、`docs/api.md`、`docs/development.md`、`docs/database.md`。画面の見た目と遷移にはユーザー提供のMiro画面遷移図PDFを使う。仕様と過去資料が異なる場合は、その後にユーザーが確定した内容を優先する。

## 担当範囲と技術

- 主な作業範囲は `apps/mobile`。React Native + Expo SDK 58 + Expo Router + TypeScript のスマートフォン向けWeb版を作る。ネイティブアプリは今回の対象外。
- カメラは `expo-camera` の `CameraView` を使う。カメラが使えないときは、撮影画面のシャッターからJPEG／PNGの画像を選べるようにする。
- 外部通信はFastAPIの公開APIを `fetch` で呼ぶ。ブラウザからSupabase、Storage、Gemini、DBへ直接接続しない。秘密鍵を `EXPO_PUBLIC_` に入れない。
- 依存を追加・変更したら `package-lock.json` を更新し、`npm run typecheck` と `npm run build:web` を確認する。ブラウザ実機での検証結果と未検証事項を分けて報告する。

## 現時点で確定したモバイルの方針

- 画面で選択するアレルゲンは29品目。⑤では少なくとも1品目を選ばないと進めず、Expo Routerの `/profiles/validate` でも検証する。食事制限4項目の欄とゲスト導線は、ユーザー指示により現在のモバイル画面から除外している。
- 利用規約は②でモーダルを開いて読んだ後に同意する。③のアカウント登録画面では同じ同意操作を繰り返さない。
- ⑥ `/map` は現時点では作成中の仮画面。撮影へ進む際は⑧で店舗を確認またはスキップする。店舗をスキップしたらPlace IDを送らず、過去の店員回答を使わない。
- ⑨ `/capture` は暗い撮影画面、⑩ `/capture/preview` は白い写真確認画面とし、Miro図の配置を基準にする。店舗名は確定済みの場合だけ⑨に表示する。
- 新規登録、ログイン、アレルゲン保存、メニュー解析の外部API URLは `src/api/endpoints.ts` に空欄で置く。最後のAPI結合まで実URLを書かず、URLが空なら外部送信しない。ユーザーが接続を指示するまでは本番DBへの書き込みを発生させない。
- 解析はログイン済みのアカウント用トークンを使う。ゲストへの自動切替や、401後の無認証再送は行わない。

## 撮影・解析の必須ルール

- ⑨の撮影だけでは画像を送らない。⑨→⑩の画像はメモリに保持し、`Retake` で破棄する。⑩の `Analyze` を押したときだけ `POST /menus/analyze` を呼ぶ。
- APIに渡す画像はJPEG／PNG、2 MiB以下、2000万画素以下。送信前に形式・寸法・容量を確認し、必要な縮小・圧縮を行う。サーバー側の再検証も前提とする。
- 解析リクエストは `multipart/form-data` の `image`、選択した `allergen_ids`、`locale=en`、選択済みなら `google_place_id` を使う。選択したアレルゲンは予測対象にだけ使い、メニューや公開回答に紐づけて保存しない。
- 解析中は二重送信を防ぎ、アプリ側の待機上限を45秒とする。失敗した解析POSTを自動再送せず、⑩で再試行・再撮影を案内する。成功時は `menu_id` で⑪へ進み、解析用トークンをURLに載せない。
- 写真、Authorization、解析用トークン、メール、パスワード、座標、アレルゲン選択をログへ出さない。画像は公開しない。

## 結果・店員確認に進むときのルール

- 利用者画面は英語、店員向け⑬・⑭は日本語。料理名は原文と英訳を区別する。
- AIの予測と店員の回答を明確に分ける。「安全」「食べられる」「公式確認済み」と断定しない。情報がないことを「含まれない」の根拠にしない。店員への再確認を促す。
- 店員の回答は4択で初期選択なし。「分からない」は有効な回答だが、不使用を示す票には数えない。⑬の回答は下書きに留め、⑭の同意と一括で保存する。
- 公開の可否をフロントだけで決めない。店舗の選択、利用者・店員の同意、APIの保存結果を確認し、非公開の回答や画像を公開画面へ出さない。
