# ⑧ 店舗確認・⑨ 撮影・⑩ 撮影確認・⑪ 解析結果

画面はユーザー提供のMiro PDFの⑧〜⑪（店舗確認、暗い撮影画面、写真確認、解析結果）を基準にする。要件はリポジトリの `requirements.md` R02・R03、通信契約は `docs/api.md` API 4を参照する。

## 現在の導線

`/map` の `Scan a menu` → `/places/select` の `Skip`（店舗IDが渡された場合は `Confirm` も表示）→ `/capture` → `/capture/preview` → `Analyze` 成功時に `/menu?id=...`。店舗候補を取得する画面は未実装なので、現時点の通常導線はスキップとなる。⑨の撮影・画像選択ではAPIを呼ばず、⑩の `Analyze` でだけ送信する。

## 技術と保持する状態

- Expo SDK 58対応の `expo-camera` の `CameraView` と `useCameraPermissions` を使う。Web版のカメラ利用にはHTTPSまたはlocalhostが必要。権限拒否・非対応時はJPEG／PNGのファイル選択を使える。
- 撮影結果または選択した画像をCanvasで最大辺1600ピクセルのJPEGに変換する。入力は2000万画素以下、送信するファイルは2 MiB以下。画像データにEXIFを残さない。サーバーも画像形式・容量・画素数を再検証する。
- `CaptureContext` が画像の `File` とプレビュー用Object URLを⑨〜⑩の間だけメモリに保持する。`Retake` は画像を破棄し、店舗IDを保ったまま⑨へ戻る。⑩を直接開いて画像がない場合は⑨へ案内する。
- ⑤でサーバー側の選択検証が成功したアレルゲンIDを、このタブの `sessionStorage` に保存する。⑩の送信直前に読み出す。1品目もない場合は解析を始めず、⑤で選択するよう案内する。
- API 4は `multipart/form-data`。`image`、選択した各 `allergen_ids`、`locale=en`、店舗が確定した場合だけ `google_place_id` を含む。今回の画面ではログインを必須とし、アカウント用トークンをBearerで付ける。画像・アレルゲン情報をDBやStorageへブラウザから直接送らない。
- APIの実URLは `src/api/endpoints.ts` の `analyzeMenu` 欄に置く。現在は空欄のため外部送信しない。APIを接続したら45秒の待機上限、二重送信防止、手動再試行、401／404／413／415／422／429／502／503／504の表示を確認する。失敗したPOSTを自動再送しない。
- 成功応答は `menu_id` と解析用トークンを対応付けてこのタブに保存し、⑪へ遷移する。トークンや画像をURL・ログに入れない。⑪は現時点で料理名・価格・アレルゲン予測の概要を表示し、料理詳細・店員確認は後続実装。
